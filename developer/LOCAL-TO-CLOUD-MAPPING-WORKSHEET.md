## Required decisions per field

For every local field, record:
1. Exact local property name and example shape (use anonymized test data only).
2. Exact cloud column name and PostgreSQL type.
3. Whether the field is required, nullable, defaulted, or generated by the database.
4. Conversion rules for dates, numbers, booleans, and empty values.
5. Whether it contains a local ID referenced by another record.
6. Conflict policy when local and cloud values differ.
7. Whether it contains personal or financial information and who is allowed to access it.

## ID safety

- Never assume a browser-generated ID is a UUID.
- Do not replace IDs in-place if attendance, grades, or fee records refer to them.
- If local IDs are not suitable cloud primary keys, use a persistent local-to-cloud ID map and preserve it in backups.
- Test the mapping with disposable sample records before using real school data.
- Repeatedly syncing the same record must not create duplicates.

## Acceptance criteria before enabling sync

- [ ] Schema output has been reviewed against every mapped field.
- [ ] Every required field has a deterministic mapping.
- [ ] Local ID relationships are preserved.
- [ ] A backup can be exported and restored successfully.
- [ ] Preview displays local and cloud counts before changes.
- [ ] First upload requires explicit confirmation.
- [ ] Repeated sync is idempotent.
- [ ] Conflicts are shown and do not silently overwrite data.
- [ ] Unauthorized users cannot read or write records.
- [ ] Offline changes survive closing/reopening the browser and reconnecting.

## Current limitation

This repository workflow can prepare and review code, but it cannot execute SQL in the connected Supabase dashboard. Until the actual schema and access checks are returned, a safe field-by-field sync implementation cannot be completed honestly.
